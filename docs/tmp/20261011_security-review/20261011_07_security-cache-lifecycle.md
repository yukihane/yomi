# S3: 訳文の保存方針・期限・消去世代

- 作成日: 2026-10-11
- 基点: `origin/main` の `244fb1d`。#6、#8〜#15がマージ済み。
- ブランチ: `fix/security-cache-lifecycle`

## 対応内容

保存を既定無効とし、設定画面で明示的に有効化した場合のみ参照・保存する。設定は保護されたstorage.localに保持し、content scriptが呼べない管理APIで変更する。設定画面からの直接IndexedDB操作を廃止した。

書き込みから7日間の期限を設定する。読み取りは期限を延長せず、期限切れは参照・件数取得・起動時の整理で削除する。最大50,000件とシークレット時の参照・保存禁止を維持する。DBをversion 3に更新し、期限を持たない旧行を破棄する。

手動消去・無効化・サインアウト・認証情報の切り替え時は進行中の翻訳を中断する。DBの世代更新と全件消去を同じトランザクションで行い、保存も同じストア群のトランザクション内で世代を照合する。workerの初期化時にも世代を更新する。消去失敗は保護された設定へ記録し、再起動してもキャッシュを停止し、管理画面から再試行できる。サインアウト結果はキャッシュ消去の成否を資格情報削除・遠隔失効と分けて表示する。

## 検証と限界

既定保存の回帰テストは実装前に失敗を確認した。ユニットでは既定値、期限境界、消去時の中断、設定変更、消去失敗と再初期化後の停止・再試行を確認する。E2Eでは既定無効、有効時の再利用、期限切れ、消去・無効化・サインアウト後の遅延応答、旧DB移行を確認する。ブラウザーのDB世代だけを変更し、古い要求の保存が拒否される条件も確認する。

認証の遅いcallback・refreshとサインアウトの競合、更新後トークンの失効、サインアウト全体の待機上限は別対応。S3に認証終了までを含む当初プランの全項目が完了したとは扱わない。実workerの強制停止・復帰と実シークレットウィンドウの検証は未実施。実アカウントは使用せず、API・資格情報はテスト用の値を使用する。
