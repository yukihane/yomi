## 再開順序とリリース前の確認

1. 独立PRをレビューし、必要な競合を解決してmainへ取り込む。現時点のPR単独のマージ可能表示は、他PRを取り込んだ後の状態を保証しない。
2. #10のマージ後に#15のbaseをmainへ変更し、差分・競合と統合検証を確認してS4を取り込む。
3. #8と#15を前提にS3の保存設定・TTL・消去世代を導入し、#11・#13を含む認証の競合を解消する。
4. 新要求型に負荷制限を適用し、サイト方針・文脈送信設定と利用者向けUIを追加する。READMEも確定した仕様に更新する。
5. 統合済みコードでS1〜S4の再現を再検証する。旧DB・設定・開いたままのタブからの更新、worker再起動、DB失敗、遅延応答と消去の競合、シークレットモードを含める。

統合後の再検証と配布zipの修正コミットとの一致は、修正PRが未マージ・未リリースのため今回は未実施。releaseワークフローはdraftが返したcommitをcheckoutしてzipを作る構成であることを読み取ったが、公開済みzipの安全性や実行時のActionsロック適用まで検証済みとは扱わない。実アカウントのOAuth・失効、OpenAI側の保存条件、端末プロファイル自体の侵害も今回のモック検証では保証しない。

調査時点の報告・再現資料・計画は履歴として保持する。現在の対処状況はこのファイルと各PRを参照し、指示があるまで資料を削除しない。
