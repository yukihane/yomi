## 残作業と依存先

| 残作業                                            | 依存先                   | 次の対応                                                                                                               |
| ------------------------------------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| refresh・遅いOAuth完了・サインアウトの競合        | #16                      | 認証とキャッシュの終了世代を揃え、遅いcallbackの資格情報保存を拒否。更新後トークンの失効と認証終了全体の待機上限を実装 |
| サイト禁止・タイトル/説明文の送信設定・初回説明UI | #16                      | 保護した設定と保存管理を利用し、backgroundで送信・参照・保存を禁止。設定変更で実行中要求も中断                         |
| 文脈による命令混入の抑制                          | 文脈送信設定             | 文脈を既定無効にして最小化し、命令と区別した入力形式にする。出力ID検証は#15で導入済み                                  |
| S1〜S4と負荷制限の統合検証                        | #16、#17、認証競合の修正 | worker強制停止・復帰、旧版更新、実シークレットウィンドウ、DB失敗、認証と遅延応答の競合を検証                           |
| リリース検証                                      | 上記の修正・統合         | Actionsロックの実適用と配布zipの修正コミット一致、依存監査、更新案内を確認                                             |

#16ではサインアウト開始時にキャッシュを消去し進行中翻訳を中断するが、認証処理そのものの競合は残る。S3の当初計画全体や認証終了の安全性まで完了したとは扱わない。#11の10秒は失効HTTP要求、#17の120秒は翻訳要求の期限であり、OAuth/refreshの終了期限ではない。

#16と#17を統合した後、上表の依存を満たす順に再開する。実装されていない機能の型・設定・結果を各PRで重複実装しない。READMEは各PRの仕様変更に合わせて更新し、文脈・サイト設定の実装時にも揃える。

実アカウントのOAuth・失効、OpenAI側の保存条件、OS/プロファイル自体の侵害はモック検証の保証外。資料は指示があるまで保持する。
