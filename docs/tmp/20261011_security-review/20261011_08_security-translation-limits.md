# 翻訳要求・応答の負荷制限

- 作成日: 2026-10-11
- 基点: `origin/main` の `244fb1d`。#10・#15の構造化要求と文書情報を利用。
- ブランチ: `fix/security-translation-limits`

## 上限

| 対象                      | 上限と動作                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------- |
| 選択文・ページ1セグメント | 8,000文字。単独の長文も拒否し、切り捨てない                                                       |
| ページ1要求               | 25セグメント・原文合計20,000文字                                                                  |
| タイトル・説明文          | 1,024文字・2,048文字。超過は要求全体を拒否                                                        |
| 翻訳出力                  | 累積64,000文字。超過deltaを返す前に中断                                                           |
| APIの生応答               | 2 MiB。改行のないSSEも受信途中で中断                                                              |
| 翻訳ポート                | 1文書4接続、拡張全体16接続。未送信接続を含み、超過は明示的に拒否                                  |
| 待機                      | 接続後未送信15秒、要求開始から120秒。タイムアウト・切断・遷移・完了で枠とリスナー・タイマーを解放 |
| 画面を開く操作            | options・usage・shortcutsの管理APIをまとめて1秒に1回                                              |

文字数はJavaScriptの文字列長（UTF-16コード単位）。待機キューは設けず、上限時は再試行を案内する。1文書の枠はブラウザーが与えたtabIdとdocumentIdで分離する。新しいポートを大量に開いても枠を迂回できない。認証待ちで切断した要求は、認証完了後もAPIへ送らない。

## 検証・残る範囲

修正前に選択文・巨大セグメントの超過を受け付けるテスト失敗を確認。境界値、ページ合計、文脈、出力、改行前の生ストリーム上限、文書/全体の枠、未送信接続と応答待ちの期限、枠の二重解放防止、画面連打をユニット検証する。実content scriptの過大要求がAPIへ到達しないことと、通常翻訳の継続をE2Eで確認する。

これは利用枠や料金の総量制限ではない。ポート切断でクライアントの受信を止めても、既にOpenAIへ送信済みの処理や利用量が取り消されたことは保証しない。OAuth/refresh自体の競合と終了期限、サイト別の禁止・文脈送信設定は別対応。#16の保存管理とは独立したmain起点のPRであり、両PR統合後は再検証が必要。
